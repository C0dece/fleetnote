# Fleetnote

Markdown-база знаний в духе Obsidian: одна кодовая база на ПК (Windows / macOS / Linux)
и смартфоны (Android / iOS), заметки лежат обычными `.md`-файлами в вашей папке,
синхронизация — через любое облако.

Стек: **Tauri v2 + React 19 + TypeScript + Vite + Tailwind v4 + CodeMirror 6 + Zustand**.
Полное ТЗ и план по фазам — в [`SPEC.md`](./SPEC.md).

---

## Быстрый старт на ПК

Нужны: **Node 22+**, **Rust 1.77+** и системные зависимости Tauri
(см. <https://v2.tauri.app/start/prerequisites/>; на Ubuntu это `libwebkit2gtk-4.1-dev`,
`libgtk-3-dev`, `librsvg2-dev`, `patchelf`).

```bash
npm install
npm run app:dev      # приложение Tauri с доступом к настоящим файлам
```

Без Rust можно посмотреть интерфейс в браузере — откроется демо-база в памяти:

```bash
npm run dev          # http://localhost:1420
```

Сборка установщиков (`.msi` / `.dmg` / `.AppImage` / `.deb`):

```bash
npm run app:build
```

Мобильные сборки (после того, как установлены Android Studio / Xcode):

```bash
npm run android:init && npm run android:dev
npm run ios:init && npm run ios:dev
```

Прочие команды: `npm test` (юнит-тесты), `npm run typecheck`, `npm run build`
(фронтенд), `npm run format`, `./pack.sh` (архив проекта для переноса).

## Что уже работает

| Фаза из SPEC.md                                     | Состояние                                                  |
| --------------------------------------------------- | ---------------------------------------------------------- |
| 1. Каркас, локальное хранилище, адаптивная оболочка | готово                                                     |
| 2. Редактор, ссылки, граф, поиск, палитра команд    | готово                                                     |
| 3. Движок синхронизации и 4 облачных адаптера       | готово, облака требуют боевой проверки с вашими аккаунтами |
| 4. Мобильная эргономика                             | готово в вебе; `tauri android/ios init` ещё не запускался  |
| 5. Тесты, оптимизация, релизные сборки              | частично: юнит-тесты ядра, виртуализация дерева            |

Подробности:

- **Local-first.** Редактор пишет в локальную папку мгновенно; сеть никогда не держит ввод.
- **Live Preview.** Разметка скрывается на строках без курсора, чекбоксы кликабельны,
  `[[ссылки]]` открываются одним кликом, `#теги` фильтруют базу.
- **Граф.** Обратные ссылки, исходящие ссылки, битые ссылки (создаются одним нажатием),
  локальный граф, оглавление.
- **Поиск.** MiniSearch в памяти: нечёткий, с префиксами, с подсветкой фрагмента;
  быстрое открытие заметки — `Ctrl/Cmd + O`, палитра команд — `Ctrl/Cmd + K`.
- **Синхронизация.** Манифест `.fleetnote/sync-manifest.json` (путь, sha256, mtime),
  фоновый push с debounce 1.5 с, очередь переживает офлайн и перезапуск,
  трёхстороннее слияние по теневой копии `.fleetnote/base/`, при пересечении правок —
  файл `… (Conflict ГГГГ-ММ-ДД ЧЧ-мм).md`.
- **Мобильный режим.** Шторки вместо панелей, нижняя навигация в зоне большого пальца,
  надклавиатурный тулбар на `visualViewport`, учёт `safe-area`, свайп назад, цели ≥ 44px.
- **Раскладка как в Obsidian.** Дерево панелей: вкладки перетаскиваются мышью внутри
  панели и между панелями, бросок к краю делит экран, разделители тянутся, пустая панель
  закрывается сама.
- **Три режима заметки.** Исходник со всей разметкой, живое превью, режим чтения.
  Плюс панель быстрых вставок и меню по «/» (заголовки, списки, таблица, выноски, дата).
- **Свойства заметки.** Типизированные поля из YAML-блока: текст, число, дата, флажок,
  список. Свои поля добавляются кнопкой.
- **Граф и холст.** Глобальный граф с силовой раскладкой, фильтрами и зумом; холст
  `.canvas` (формат совместим с Obsidian): карточки заметок и текста, связи, цвета.
- **Иерархия.** Папки создаются в любом месте, файлы и папки переносятся
  перетаскиванием (мышью и пальцем), заметки закрепляются наверху списка.
- **Настройки.** Шесть разделов: вид (тема, акцент, шрифты, кегль, межстрочный,
  ширина колонки, масштаб, рамка окна), редактор, хранилище, синхронизация,
  мобильные, экспорт и импорт настроек файлом.
- **Файлы любого типа.** Картинки, PDF, звук, видео, текст и всё остальное кладутся
  в базу кнопкой, перетаскиванием из проводника или вставкой. Они видны в дереве,
  открываются вкладкой (а что приложение не рисует — системным приложением) и
  синхронизируются наравне с заметками.
- **Вложения в тексте.** `![[картинка.png]]` и обычные Markdown-картинки видны и в
  живом превью, и в режиме чтения; `![[Заметка]]` разворачивается блоком.
  Markdown-таблицы рисуются сеткой, исходник открывается по курсору.
- **Вход в Google в один клик.** Приложение поднимает локальный порт, ловит редирект
  само — копировать код не нужно. Пароли и токены лежат в системном хранилище
  секретов (Keychain, Credential Manager, Secret Service), а не в localStorage.

## Вход в Google «нажал и всё»

Приложение умеет работать с вшитым OAuth-клиентом — ровно так же, как это делают
rclone и плагины Obsidian. Google для установленных приложений client secret
секретом не считает: он в любом случае оказывается внутри бинарника у каждого
пользователя.

Создайте клиент один раз (console.cloud.google.com → APIs & Services →
Credentials → Create credentials → OAuth client ID → **Desktop app**) и положите
значения туда, где их возьмёт сборка:

- **для релизов**: GitHub → репозиторий → Settings → Secrets and variables → **Actions** →
  вкладка **Secrets** → New repository secret. Именно эта страница: секреты из
  Codespaces, Dependabot и из настроек окружения Claude сборке не видны.
  Имя — `DESKTOPCLIENT` (принимаются также `GDRIVE_CLIENT_JSON`, `GOOGLE_CLIENT_JSON`,
  `DESKTOP_CLIENT`, `GDRIVE_CLIENT`), значение — JSON-файл, который отдала консоль.
  Можно вместо него положить пару `GDRIVE_CLIENT_ID` и `GDRIVE_CLIENT_SECRET`;
  формат значения любой: целый файл, его внутренности без внешних скобок или
  просто строки с `client_id` и `client_secret`.
  Проверка: к каждому релизу прикладывается `build-info.json` — там видно, какой
  секрет подхватился и нашлись ли ключи (сами значения в отчёт не попадают);
- **локально**: скопируйте `.env.example` в `.env.local` и заполните (файл в `.gitignore`).

После этого в настройках синхронизации не спрашиваются никакие ключи — остаётся
одна кнопка «Войти через Google». Без секретов сборка тоже проходит: приложение
просто попросит пользователя создать собственный клиент.

Важно: пока OAuth-приложение в статусе **Testing**, войти смогут только добавленные
тест-пользователи, а доступ придётся продлевать раз в неделю — Google гасит токены
тестовых пользователей через 7 дней. Для постоянной работы переведите приложение в
**Production**; область `drive.file` у Google относится к несенситивным, поэтому
проверка проходит по упрощённому пути.

### Если консоль Google трогать не хочется

Подключите WebDAV: Nextcloud, свой сервер или Яндекс.Диск (нужен Яндекс 360).
Там вход — обычные логин и пароль приложения, никаких OAuth-клиентов. Пароль
приложения для Яндекса создаётся на странице паролей приложений, адрес сервера —
`https://webdav.yandex.ru`.

## Структура

```
src/
├── core/
│   ├── fs/          # VaultFs: Tauri-ФС и память (демо-режим), работа с путями
│   ├── vault/       # разбор Markdown, VaultManager, граф ссылок
│   ├── index/       # MiniSearch + кэш метаданных в SQLite
│   └── sync/        # IStorageAdapter, SyncEngine, манифест, 3-way merge, адаптеры
├── components/      # layout (панели и вкладки), editor, views (граф, холст), navigation, settings
├── stores/          # Zustand: vault, editor, sync, ui
├── hooks/           # медиазапросы, visualViewport, горячие клавиши
└── styles/          # токены тем (Warm Paper / Graphite / AMOLED) и утилиты safe-area
src-tauri/           # Rust-часть: плагины fs, dialog, sql, os, opener; capabilities
```

## Версия одним файлом

```bash
npm run build:single      # → dist-single/fleetnote.html
```

Получается самодостаточный HTML (~1.5 МБ): скрипты, стили и иконка внутри,
внешних запросов нет. Открывается двойным кликом с диска в любом браузере —
удобно, чтобы быстро показать интерфейс там, где нет ни Node, ни Rust.
Заметки в этом режиме живут в памяти браузера, доступа к файлам ПК нет.

## Готовые установщики без локальной сборки

В репозитории лежит `.github/workflows/build.yml`: после пуша на GitHub вкладка **Actions →
Сборка приложения → Run workflow** собирает `.msi`/`.exe`, `.dmg` и `.AppImage`/`.deb` на машинах
GitHub и кладёт их в артефакты запуска. Пуш тега `v0.1.0` дополнительно создаёт черновик релиза.
Локально при этом не нужны ни Rust, ни Visual Studio, ни Xcode.

## Подключение облака

Настройки → «Синхронизация». Доступны четыре адаптера:

- **Папка на диске** — путь к папке, которую синхронизирует Google Drive Desktop,
  Syncthing, iCloud или NAS. Самый надёжный вариант на ПК.
- **WebDAV** — Nextcloud, Яндекс.Диск, ownCloud: адрес, логин, пароль приложения, папка.
- **Google Диск** — нужен OAuth Client ID («Desktop app», PKCE, без client_secret).
  Сейчас вход двухшаговый: кнопка открывает страницу Google, затем вы вставляете `code`
  из адресной строки редиректа. Автоматический loopback-перехват — в списке доработок ниже.
- **S3 / R2 / MinIO** — бакет, регион, endpoint, ключи. SDK подгружается только при выборе.

Параметры хранятся в `localStorage` приложения. Это значит, что **токены и ключи лежат в
открытом виде** — для личной машины приемлемо, для рабочей стоит перенести их в системное
хранилище (см. ниже).

## Что доработать дальше

1. **OAuth без копипасты**: поднять loopback-сервер на Rust-стороне и ловить редирект сам.
2. **Секреты в keychain** вместо `localStorage` (`tauri-plugin-stronghold` или ОС-хранилище).
3. **Индексация в Web Worker** и стресс-тест на 5 000+ заметок (сейчас сканирование идёт
   в основном потоке; дерево виртуализировано, результаты поиска — нет).
4. **Просмотр вложений**: вставка картинок работает, рендер `![[картинка.png]]` в тексте — нет.
5. **Боевая проверка облаков** с реальными аккаунтами Google / Nextcloud / R2.
6. **`tauri android init` / `ios init`** и прогон на устройствах.
